---
title: Why @iamsquare/ua
description: Structured User-Agent parsing for messy real-world strings
---

User-Agent detection is messy. Real strings mix browsers, WebViews, apps, and device noise. `@iamsquare/ua` turns them into a typed object you can work with.

## Real-world User-Agents are full of surprises

Suppose a visitor sends this (yes, it's a real string):

```ts
const ua = `Mozilla/5.0 (iPhone; CPU iPhone OS 10_3_1
like Mac OS X) AppleWebKit/603.1.30 (KHTML, like Gecko)
Mobile/14E304 [FBAN/FBIOS;FBAV/91.0.0.41.73;FBBV/57050710;
FBDV/iPhone8,1;FBMD/iPhone;FBSN/iOS;FBSV/10.3.1;FBSS/2;
FBCR/Telekom.de;FBID/phone;FBLC/de_DE;FBOP/5;FBRV/0])`;
```

Parse it:

```ts
import { parseUA } from '@iamsquare/ua';
import { BrowserName, DeviceType, EngineName, OSName } from '@iamsquare/ua/enums';
import { isBrowser, isDevice, isEngine, isOS } from '@iamsquare/ua/helpers';

const result = parseUA(ua);

result.browser;
// { name: "Facebook", version: "91.0.0.41.73", major: "91", type: "inapp" }

result.engine;
// { name: "WebKit", version: "603.1.30" }

result.device;
// { type: "mobile", vendor: "Apple", model: "iPhone" }

result.os;
// { name: "iOS", version: "10.3.1" }

isBrowser(result.browser, BrowserName.FACEBOOK);
isOS(result.os, OSName.IOS);
isDevice(result.device, DeviceType.MOBILE);
isEngine(result.engine, EngineName.WEBKIT);
```
