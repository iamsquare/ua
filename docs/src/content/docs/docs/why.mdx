---
title: Why @iamsquare/ua
description: Structured User-Agent parsing for messy real-world strings
---

User-Agent detection is messy. Real strings mix browsers, WebViews, apps, and device noise. `@iamsquare/ua` turns them into a typed result.

## Real-world User-Agents are full of surprises

Suppose a visitor sends this (a real string):

```ts
const ua = `Mozilla/5.0 (Linux; Android 10; STK-LX1
Build/HONORSTK-LX1; wv) AppleWebKit/537.36 (KHTML,
like Gecko) Version/4.0 Chrome/110.0.5481.153 Mobile
Safari/537.36 musical_ly_2022803040 JsSdk/1.0
NetType/WIFI Channel/huaweiadsglobal_int
AppName/musical_ly app_version/28.3.4 ByteLocale/en
ByteFullLocale/en Region/IQ Spark/1.2.7-alpha.8
AppVersion/28.3.4 PIA/1.5.11 BytedanceWebview/d8a21c6`;
```

Parse it:

```ts
import { parseUA } from '@iamsquare/ua';
import { BrowserName, DeviceType, EngineName, OSName } from '@iamsquare/ua/enums';
import { isBrowser, isDevice, isEngine, isOS } from '@iamsquare/ua/helpers';

const result = parseUA(ua);

result.browser;
// { name: "TikTok", version: "28.3.4", major: "28", type: "inapp" }

result.engine;
// { name: "Blink", version: "110.0.5481.153" }

result.device;
// { type: "mobile", vendor: "Honor", model: "STK-LX1" }

result.os;
// { name: "Android", version: "10" }

isBrowser(result.browser, BrowserName.TIKTOK);
isOS(result.os, OSName.ANDROID);
isDevice(result.device, DeviceType.MOBILE);
isEngine(result.engine, EngineName.BLINK);
```
